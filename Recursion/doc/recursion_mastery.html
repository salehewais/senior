Chapter 1

Recursion Mental Model

هدف التعلم: تقدر تشرح الـ recursion لجملة واحدة، وتفرّق بينه وبين الـ iteration، ومن غير ما تخلط بينه وبين أي function بتنادي function تانية.

الـ recursion إن الـ function بتحل المسألة عن طريق نسخة أصغر أو أقرب من نفس نوع المسألة، وتسيب الـ call stack يفتكر كل نسخة لحد ما نسخة صغيرة تقدر تخلص لوحدها.

الحلول الـ recursive موجودة لأن في مسائل تعريفها كده أصلًا: مجلد جواه مجلدات، قوس جواه أقواس، شجرة يمينها وشمالها شجر. لما تكتب الحل بنفس شكل المسألة، الكود بيبقى أقصر في التعبير، والـ stack بيبقى هو ذاكرة «أنا كنت فين».

المسألة الكبيرة والنسخة الأصغر

خد مجموع قائمة. مجموع [1, 2, 3] هو 1 زائد مجموع [2, 3]. نفس السؤال، على قائمة أقصر. لما القائمة تفضى، المجموع صفر. من غير الخطوة الأخيرة دي مفيش مكان تقف فيه.

sum [2,3]2 + الباقي
→
sum [3]3 + الباقي

sum []0 وتبدأ الرجوع

الفرق عن الـ iteration

كل نداء له stack frame فيها المتغيرات المحلية بتاعتها. النداء الحالي بيتعلّق لما ينادي نسخة أصغر، ويرجع يكمّل لما النسخة دي تخلّص. الـ stack هو اللي حافظ ترتيب الرجوع.

الـ loop بيشتغل في frame واحدة. إنت اللي بتحدّث المتغيرات وبتقرر إمتى تخرج. مفيش نداء معلّق. في الـ linear recursion الكتير من الشغل ده يتحول لـ loop، وفي الشجر والأقواس المتداخلة الـ stack الجاهز بيوفّر عليك بناء stack بإيدك.

الـ recursion بيبقى أسهل في التعبير لما بنية المسألة متشابهة ذاتيًا: شجرة، أقواس متداخلة، تقسيم لنصين، أو بحث بتجربة خطوة ورجوها. مش كل مسألة كده. لو الحالة عبارة عن عداد بسيط ومافيش نتيجة محتاجة تترجع وتندمج، الـ loop غالبًا أوضح وأرخص في الـ stack.

مثال صغير

Python · countdown
def countdown(n):
    if n == 0:
        return
    print(n)
    countdown(n - 1)

أفكار بتتلخبط كتير

نداء function تانية

a() بتنادي b() من غير ما b ترجع لسلسلة توصل تاني لـ a. ده مش recursion. الـ recursion المباشر إن الـ function تنادي نفسها، وغير المباشر (mutual recursion) إن في دائرة نداءات ترجع لنفس المسألة.

وجود base case

كتابة شرط توقف من غير ما التنفيذ يقدر يوصله بتسيب النداءات ماشية للأبد لحد RecursionError. التوقف محتاج شرط، ومحتاج تقدم حقيقي ناحيته.

فرعين دائمًا

في recursion بنداء واحد بس، زي الـ countdown. الفرعين أو أكتر نمط تاني اسمه tree recursion، وبيتشرح في الفصل 7 لوحده.

النسيان

النداء الأعمق ما بيمسحش النداء اللي فات. النداء القديم معلّق، ومتغيراته لسه موجودة، وهيرجع يكمّل من بعد سطر النداء.

في mutual recursion، is_even تنادي is_odd والعكس. التقدم لسه موجود: n بيقل واحد لحد ما يوصل لصفر.

Python · mutual recursion
def is_even(n):
    if n == 0:
        return True
    return is_odd(n - 1)

def is_odd(n):
    if n == 0:
        return False
    return is_even(n - 1)

is_even(4) ترجع True. السلسلة: even(4) → odd(3) → even(2) → odd(1) → even(0).

أخطاء شائعة

  • تعتبر أي كود فيه نداء function إنه recursive.
  • تفتكر إن الـ recursion أبطأ دائمًا أو أجمل دائمًا. الحكم على بنية المسألة وعلى تكلفة الـ stack.
  • تكتب شرط التوقف وتنسى تغيّر الحاجة اللي الشرط بيفحصها.

أسئلة مراجعة

ليه مجموع القائمة مثال مناسب للـ recursion؟

لأن مجموع القائمة = أول عنصر + مجموع الباقي. الباقي نفس المسألة على حجم أصغر، والقائمة الفاضية إجابة جاهزة.

إيه اللي الـ iteration بتخليه في متغيرات، والـ recursion بتسيبه للـ stack؟

مكان الوقوف في المسألة، والقيم المحلية بتاعة كل خطوة لسه محتاجاها بعد الرجوع.

الخلاصة

  • الـ recursion تعبير عن نفس المسألة على حالة أقرب للتوقف.
  • الـ call stack بيحفظ النداءات المعلّقة. النداء الأعمق ما بيمسحهاش.
  • الـ base case من غير progress مش هيوقف التنفيذ.

Chapter 2

The Anatomy of a Recursive Function

هدف التعلم: تقدر تشاور على أي recursive function وتسمي مكوناتها، وتفهم ليه شرط التوقف لوحده مش كفاية.

المكونات دي عدسة للفهم، مش سبع بلوكات لازم تظهر بالترتيب في الكود. أحيانًا سطر واحد فيه الـ state والنداء والتقدم مع بعض.

اسحب الجدول أفقيًا لو الشاشة ضيقة.

Python · المكونات على مثال واحد
def countdown(n):
    if n == 0:          # base case
        return          # return value is None
    print(n)            # logic for this call
    countdown(n - 1)    # recursive call + progress

ليه الـ base case لوحده مش ضمان

التقدم يعني إن حالة التنفيذ بتتحرك ناحية شرط توقف صحيح. الشرط المكتوب في أول الـ function بيتنفّذ بس لو مسار النداءات يوصله.

Python · base case موجودة ومش بتتوصل
def countdown_broken(n):
    if n == 0:
        return
    print(n)
    countdown_broken(n + 1)

متشغّلش المثال ده على مدخل كبير. n بيزيد، فشرط n == 0 مش هيتحقق. Python هيقف عند حد عمق الـ recursion ويرمي RecursionError. وجود الشرط في الكود غير وصول التنفيذ له.

نفس الفكرة لو الـ index واقف مكانه:

Python · مفيش تقدم في الـ index
def walk(s, index):
    if index >= len(s):
        return
    walk(s, index)

الـ base case صح، لكن النداء بيعيد نفس الـ index. التقدم هنا كان المفروض يبقى index + 1.

أخطاء شائعة

  • تحط الـ recursive call في فرع الـ base case نفسه.
  • تغيّر متغير محلي بعد ما تبعت القيمة القديمة للنداء، وتفتكر إن النداء شاف التغيير. اللي اتبعت هو قيمة المعامل ساعة النداء.
  • تعتبر إن return جوه الـ base case بيرجع من كل النداءات المفتوحة مرة واحدة. هو بيرجع من النداء الحالي بس.

أسئلة مراجعة

إيه الـ state في countdown؟

العدد n المتبقي. هو اللي بيوصف «إحنا فين في المسألة».

إزاي progress في countdown_broken مكسور؟

النداء بيزود n، بينما شرط التوقف محتاج n يوصل لصفر. الاتجاه عكس الشرط.

الخلاصة

  • المكونات عدسة، وممكن تتلم في سطور قليلة.
  • الـ base case لازم يكون reachable عن طريق progress واضح.
  • مش كل function لازم ترجع قيمة محسوبة. أحيانًا الأثر هو الطباعة أو تعديل حالة خارجية، وده له ثمن في سهولة الاختبار.

Chapter 3

Call Stack and Execution Order

هدف التعلم: تقدر ترسم الـ stack بإيدك، وتفرّق بين الشغل وقت النزول والشغل وقت الرجوع.

لما Python تنفّذ function، بتفتح stack frame جديدة: مكان للمعاملات والمتغيرات المحلية، ومكان يفتكر السطر اللي المفروض نرجعله. النداء العادي بيعمل كده. النداء الـ recursive بيعمل نفس الحاجة، بس الـ frames بتكدّس نسخ من نفس الـ function.

لما النداء الحالي يوصل لسطر recursive call، الإطار بتاعه بيتعلّق. المتغيرات اللي جواه لازم تفضل موجودة، لأن في سطور بعد النداء ممكن تحتاجها. النداء الجديد يشتغل فوقيه. لما النداء الجديد يرجع، الإطار القديم يكمّل من السطر التالي.

نزول ورجوع

Descent

من النداء الأول لحد الـ base case. الشغل المكتوب قبل الـ recursive call بيظهر في الطريق ده.

Unwinding

من الـ base case رجوعًا للمستدعي الأول. الشغل المكتوب بعد الـ recursive call بيظهر في الطريق ده، والعكس في ترتيب الإطارات.

Python · before / after
def countdown(n):
    if n == 0:
        print("done")
        return
    print("before", n)
    countdown(n - 1)
    print("after", n)

    Stack overflow وحد العمق

    كل frame بتاخد ذاكرة. CPython عنده حد افتراضي لعمق الـ recursion، غالبًا 1000، وتقدر تشوفه بـ sys.getrecursionlimit(). لو سلسلة النداءات أطول من الحد، التنفيذ يوقف بـ RecursionError حتى لو الـ base case كانت هتوصل بعد شوية.

    ده فشل مختلف عن الـ recursion اللي مش بتتقدم. في الحالة الأولى التقدم موجود والحد هو اللي قاطع الطريق. في الحالة التانية مفيش مسار يوصل للشرط حتى لو الذاكرة بلا نهاية. رفع الحد بـ sys.setrecursionlimit مش إصلاح لتصميم بيكسر التقدم، وممكن يخلي العملية تقع بدل ما ترمي استثناء واضح.

    • تفتكر إن print بعد النداء هيظهر قبل ما النداءات الأعمق تشتغل.
    • ترسم الـ stack من غير ما تميز القمة. أول نداء هو القاع، وآخر نداء لسه ما رجعش هو القمة.
    • تحسب إن الرجوع من الـ base case بيقفل كل الإطارات من غير ما تنفّذ السطور المؤجلة.

    Chapter 4 · الفصل المركزي

    Recursive Call Roles

    هدف التعلم: تميّز مسؤولية الـ call: هل بتحدّث الحالة وتسلّم التكملة، ولا بتستنى نتيجة subproblem وتعالجها؟ وتسيب التصنيفات الرسمية زي Tail Recursion في فصلها.

    أثناء تحليل Decode String بيظهر نوعين من الشغل. التسميات تحت دي عناوين تعلم عشان نصف المسؤولية. هي مش تصنيف أكاديمي متفق عليه عالميًا، ومش خانات لازم كل خوارزمية تقع في واحدة منهم بس.

    بعض الشروحات بتستخدم ألفاظ زي Action Recursion و Decision Recursion. الألفاظ دي تعليمية وغير معيارية. سهلة تخلط التقدم نحو التوقف مع «عمل»، أو تخلط معالجة النتيجة مع «قرار بين فرعين». المرجع ده مش بيعتمدهم. التقدم مفهوم لوحده، واتشرح في الفصل 2. القرار بين فرعين اسمه branching، وبيتشرح في الفصل 7.

    Continuation / State-Progression Role

    النداء الحالي بيخلّص شغله على الحرف أو الخطوة، يحدّث الـ state، ويسلّم النسخة الجديدة. نتيجة النداء الجاي بترجع كما هي.

    Recursive-Result Processing Role

    النداء الحالي بيطلب subproblem، يستنى نتيجتها، يدمجها أو يحوّلها، وبعدين يكمّل. في قيمة راجعة بتتستخدم، مش بس بتتعاد.

    Role A — Continuation / State-Progression

    بالمصري: النداء ده بيحدّث الحالة ويمشي المؤشر، وبعدين يسلّم التكملة. هو مش مستني يفك نتيجة عشان يبني منها حاجة جديدة.

    English: This call updates state, advances the input position, passes that state forward, and returns the recursive result directly.

    Tail Recursion vs Non-Tail Recursion

    هدف التعلم: تحكم على موضع النداء من الشغل المؤجل بعده، وتعرف إن CPython مش بيحول الـ tail call لقفزة، فاستهلاك الـ stack بيفضل موجود.

    الفصل ده مستقل عن الفصل 4. Tail position يعني إن النداء آخر فعل في الإطار، ومفيش حساب بيستخدم ناتجه بعد الرجوع. Pending work هو أي حاجة لازم تتنفذ بعد الرجوع: طباعة، جمع، لصق نص، أو نداء تاني بيعتمد على الناتج.

    Python
    def print_down(n):
    if n == 0:
        return
    print(n)
    return print_down(n - 1)

    الطباعة قبل النداء. بعد النداء مفيش غير إن نتيجته هي قيمة الـ return. الموضع tail. مخرجات print_down(4) هي 4 ثم 3 ثم 2 ثم 1.

    Python
    def print_up(n):
    if n == 0:
        return
    print_up(n - 1)
    print(n)

    النداء مش آخر فعل. print(n) مؤجل لحد الرجوع. الإطار لازم يفضل على الـ stack. مخرجات print_up(4) هي 1 ثم 2 ثم 3 ثم 4.

    في return n * fact(n - 1) الضرب pending work. النداء مش في tail position حتى لو هو النداء الوحيد. لو حبينا ننقل الشغل للمعامل، الشكل يتغير:

    fact_acc(5) ترجع 120، زي fact(5). الضرب حصل قبل النداء، واتخزن في acc. الموضع بقى tail. المسؤولية هنا أقرب لدور الاستمرار: الحالة المحدّثة هي acc. وبرضه ده مش بيخلي Tail Recursion و Continuation اسمين لحاجة واحدة. تقدر تلاقي tail call قراره اتعمل قبل النداء، زي فرع الـ binary search، من غير ما يكون «تحديث رقم خانة».

    ليه Python مش بتوفّر الذاكرة تلقائيًا

    CPython لا يعمل Tail Call Optimization. النداء في tail position لسه بيفتح frame جديدة، والقديمة بتستنى الرجوع. سلسلة طولها n بتاخد عمق stack من رتبة n، سواء print_down أو fact_acc. الشكل الـ tail في Python فائدته في وضوح «مفيش شغل بعد النداء»، مش في تقليل الذاكرة. حد العمق لسه موجود، و fact_acc(10000) ممكن يرمي RecursionError زي النسخة غير الـ tail.

    لو شيلت return من print_down وخليت النداء آخر سطر، برضه مفيش استخدام للناتج بعد الرجوع. كتابة return print_down(...) بتبيّن الموضع بوضوح. في الحالتين CPython بيحتفظ بالإطار.

    أخطاء شائعة

    • تسمي continuation و tail recursion مترادفين.
    • تفتكر إن نقل الحساب لـ accumulator بيخلّي الحل O(1) stack في Python.
    • تشوف نداء في آخر سطر وتتجاهل عملية على نفس السطر بتستخدم ناتجه، زي return n * fact(n - 1).

    أسئلة مراجعة

    إيه الـ pending work في print_up؟

    طباعة n بعد رجوع النداء. من غيرها الإطار مش محتاج يستنى حاجة خاصة بيه.

    هل fact_acc أوفر في stack من fact على CPython؟

    الاتنين عمقهم من رتبة n. الفرق في موضع الحساب، مش في تحسين تلقائي من المترجم.

    الخلاصة

    • Tail position = مفيش شغل بيستخدم الناتج بعد النداء.
    • Non-tail = في pending work، فالإطار جزء من معنى الحساب.
    • في Python الاتنين بيستهلكوا stack. الـ TCO مش موجودة في CPython.

    Return Values and State Management

    هدف التعلم: تقرر إيه يمشي للأمام في المعاملات، وإيه يرجع للمستدعي، وإمتى النتيجة تبقى مركبة زي نص مع index.

    المعلومة اللي النداءات الجاية هتكمل بيها، والنداء الحالي خلّص حسابها، تمشي كمعامل. مثال: acc في fact_acc، و current_num أثناء قراءة الخانات.

    المعلومة اللي الإطار الحالي لسه هيدمجها مع حاجة عنده، أو اللي المستدعي الأصلي عايزها، ترجع كـ return. مثال: ناتج fact، ومجموع القائمة.

    أحيانًا المستدعي محتاج الناتج ومحتاج يعرف التنفيذ وقف فين. Decode String بترجع (string, index). النص هو المنتج، والـ index هو مكان استئناف القراءة. الفصل 8 هيبني السبب من المسألة نفسها.

    قبل النداء

    نسخة الفصل 1 بتطبع وبتراجع None. مفيش قيمة محتاجة تتدمج. لو حد كتب return countdown(n - 1) القيمة لسه None. الأثر الحقيقي هو ترتيب الطباعة، وده side effect. الـ factorial من غير return مستخدم يضيع الناتج، لأن كل الإطار بيعمل هو إنه يضرب الرقم في ناتج الأصغر.

    rsum بتنسخ باقي القائمة في كل مستوى. الزمن والمساحة الإضافية من النسخ مش بس من عدد النداءات. على قائمة طولها n، الشغل الكلي من رتبة n² بسبب nums[1:]. نسخة بـ index بتبقى O(n) زمن و O(n) stack:

    def rsum_i(nums, i=0):

    • ترجع النص من غير الموضع، والمستدعي يكمل من index قديم.
    • تبعت الحالة للأمام وتنسى تستخدمها، وتحسبها تاني بعد الرجوع بقيم قديمة.
    • تعتمد على تعديل list جوه النداءات من غير ما تحدد مين مالك التعديل. في الـ backtracking التعديل المؤقت بيرجع بالعكس بعد النداء، وده نمط الفصل 7.

    إيه اللي راجع من fact، وإيه اللي راجع من countdown؟

    fact بترجع عدد متبني من النواتج الأصغر. countdown بترجع None، والمطلوب منها أثر الطباعة.

    امتى الـ return يبقى tuple؟

    لما المستدعي يحتاج أكتر من معلومة عشان يكمّل، زي الناتج ومكان الوقوف في المدخل.

    • المعامل بينقل اللي اتحسب خلاص للنداء الجاي.
    • الـ return بينقل اللي الإطار الحالي محتاجه بعد الانتظار.

    Linear Recursion

    كل نداء بيعمل recursive call واحد على حالة أقرب بخطوة. شكل السلسلة خط، مش شجرة. مناسب لما المسألة تتقسم لعنصر حالي وباقي بنفس النوع، زي قائمة أو رقم بيقل بواحد.

    if node is None:
        return 0

    غلطة شائعة: تنادي length(node) من غير ما تمشي لـ next. مسألة ممثلة: 206. Reverse Linked List بالنسخة الـ recursive، وعمق الـ stack فيها O(n).

    Tail Recursion

    وصف لموضع النداء لما يكون آخر فعل. مناسب لما تقدر تنقل الشغل المؤجل لمعامل قبل النداء. في CPython المساحة لسه O(n) stack. التفاصيل في الفصل 5. مثال: fact_acc. غلطة شائعة: اعتبارها تحسين ذاكرة في Python. مسألة قريبة: أي تجميع بمؤشر ماشي للأمام، زي عدّ الحروف في نص، لما الناتج يتبعت في معامل.

    Non-Tail Recursion

    في pending work بعد النداء. مناسب لما نتيجة الأصغر تتبنى عليها قيمة الإطار الحالي، زي العمق أو المجموع أو الطباعة وقت الرجوع. مثال الفصل 5: print_up. الزمن في المثال O(n) والـ stack O(n). غلطة شائعة: تفتكر إن الطباعة بعد النداء هتظهر أثناء النزول. مسألة ممثلة: 104. Maximum Depth of Binary Tree، وهي كمان tree recursion لأن فيها نداءين.

    Multiple Recursive Calls / Tree Recursion

    النداء الواحد بيطلق أكتر من recursive call، والاتنين بيتنفذوا. شجرة النداءات بتتفرع. مناسب لما الجزء الحالي يعتمد على أكتر من subproblem مستقل، زي فروع شجرة أو متتالية بترجع خطوتين.

    Python · fibonacci من غير memo
    def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

    fib(5) ترجع 5 بعد 15 نداء. fib(4) ترجع 3 بعد 9 نداءات. الزمن أسي تقريبًا، من رتبة O(φ^n)، والـ stack O(n) بس لأن العمق هو أطول مسار. كتير من النداءات بتعيد نفس n. غلطة شائعة: تحسب عدد الأوراق وتحسب إن المساحة أسية. المساحة تتبع العمق، والزمن يتبع عدد النداءات. مسائل: 509.     Divide and Conquer

    تقسيم المسألة لنصفين أو أكتر، حل كل جزء، ثم دمج. غالبًا النداءات شجرة متوازنة. مناسب لما الدمج أرخص من إعادة بناء الحل من الصفر، والجزءين مستقلين.

    Python · أكبر عنصر بالتقسيم
    def max_dc(a, lo, hi):
    if lo == hi:
        return a[lo]
    mid = (lo + hi) // 2
    return max(max_dc(a, lo, mid), max_dc(a, mid + 1, hi))

    max_dc([3, 1, 8, 2], 0, 3) ترجع 8. الزمن O(n) والـ stack O(log n) لو التقسيم متوازن. pow بالنصف بيقلل عدد الضرب:

    Python · power
    def pow_rec(x, n):
    if n == 0:
        return 1
    if n % 2 == 0:
        half = pow_rec(x, n // 2)
        return half * half

    Backtracking

    تجربة قرار، نداء يكمل البناء، وبعد الرجوع تلغي القرار عشان تجرب غيره. مناسب للتباديل والمجموعات والتوليد تحت قيود. النداءات شجرة اختيارات. المسار الحالي غالبًا list واحدة بتتعدل وتترجع، عشان متعملش نسخة في كل مستوى.

    Python · subsets
    def subsets(nums):
    result = []

    def choose(i, path):
        if i == len(nums):
            result.append(path[:])
            return
        path.append(nums[i])
        choose(i + 1, path)
        path.pop()
        choose(i + 1, path)

    choose(0, [])
    return result

    def fib_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n in memo:
        return memo[n]
    if n <= 1:

    class Solution:
    def decodeString(self, s: str) -> str:
        def helper(
            index: int,
            current_num: int,
            current_str: str
        ) -> tuple[str, int]:

            if index >= len(s):
                return current_str, index

            char = s[index]

            if char.isdigit():
                return helper(
                    index + 1,
                    current_num * 10 + int(char),
                    current_str
                )

            elif char == "[":
                sub_str, next_index = helper(
                    index + 1, 0, ""
                )

                return helper(
                    next_index,
                    0,
                    current_str + (sub_str * current_num)
                )

            elif char == "]":
                return current_str, index + 1

            else:
                return helper(
                    index + 1,
                    current_num,
                    current_str + char
                )

        return helper(0, 0, "")[0]
