Overview

deploy/ is the local runtime for the commerce platform. It has no README of its own. Compose is the first runtime. Kind is a second packaging of the same image tags. Checkout does not wait on the observability stack.

  • compose/ — primary stack, project commerce, network commerce. up.sh creates JWT keys and .env when they are missing, then runs docker compose up -d --build. The only public HTTP door is Traefik on 127.0.0.1:8080.
  • gateway/ — Traefik static config, JWT ForwardAuth, and the edgeheaders plugin. gateway/compose.yaml is a host-process gateway and must not run at the same time as the full stack. Both bind port 8080. Kind and Compose reuse the plugin, the JWT image, and compose/dynamic.yaml.
  • kind/ — one-node cluster named commerce. apply.sh loads the same image tags and applies manifests. Host 127.0.0.1:8080 maps to NodePort 30080, then an ingress Traefik forwards every public path to a second Traefik, the gateway.
  • observability/ — Prometheus, Alertmanager, a log-only webhook, the OpenTelemetry collector, Tempo, Grafana dashboards, and RabbitMQ plugins. Compose bind-mounts these files. Kind turns them into ConfigMaps.
  • backup/ — pg_dump and pg_restore for order_db, reporting_db, and odoo_db only. Redis, RabbitMQ, and notification_db are not backed up.
  • load/ — Locust customer path against http://127.0.0.1:8080. Gentle mode stays under Redis limits. Flood mode expects HTTP 429.
  • failure-lab/ — stops or starts one Compose service at a time (reporting consumer, RabbitMQ, Redis, inventory consumer) and prints what should still work.

Secret files are named here by role. This page does not copy PEM bodies or the value of INTERNAL_SERVICE_TOKEN.

نظرة عامة

مجلد deploy/ هو بيئة التشغيل المحلية لمنصة التجارة. ليس له ملف README خاص. Compose هو وقت التشغيل الأول. Kind تغليف ثانٍ لنفس وسوم الصور. إتمام الشراء لا ينتظر مكدس المراقبة.

  • compose/ — المكدس الأساسي، المشروع commerce، الشبكة commerce. ينشئ up.sh مفاتيح JWT وملف .env إن غابا، ثم يشغّل docker compose up -d --build. الباب العام الوحيد لـ HTTP هو Traefik على 127.0.0.1:8080.
  • gateway/ — إعداد Traefik الثابت، وفحص JWT عبر ForwardAuth، وإضافة edgeheaders. ملف gateway/compose.yaml بوابة لعمليات على الجهاز المضيف، ولا يُشغَّل مع المكدس الكامل في الوقت نفسه. كلاهما يربط المنفذ 8080. تعيد Kind وCompose استخدام الإضافة وصورة JWT وملف compose/dynamic.yaml.
  • kind/ — عنقود من عقدة واحدة اسمه commerce. يحمّل apply.sh وسوم الصور نفسها ويطبّق البيانات. يُقابل 127.0.0.1:8080 على المضيف منفذ العقدة 30080، ثم يمرّر Traefik الدخول كل مسار عام إلى Traefik ثانٍ هو البوابة.
  • observability/ — Prometheus وAlertmanager وخطاف يسجّل في السجل فقط، ومجمّع OpenTelemetry، وTempo، ولوحات Grafana، وإضافات RabbitMQ. يربط Compose هذه الملفات مباشرة. تحوّلها Kind إلى ConfigMaps.
  • backup/ — pg_dump وpg_restore لقواعد order_db وreporting_db وodoo_db فقط. Redis وRabbitMQ وnotification_db غير مشمولة بالنسخ.
  • load/ — مسار زبون Locust نحو http://127.0.0.1:8080. الوضع الهادئ يبقى تحت حدود Redis. وضع الغمر يتوقع HTTP 429.
  • failure-lab/ — يوقف أو يشغّل خدمة Compose واحدة في كل مرة (مستهلك التقارير، RabbitMQ، Redis، مستهلك المخزون) ويطبع ما يُفترض أن يبقى عاملاً.

تُذكر ملفات الأسرار هنا بدورها فقط. هذه الصفحة لا تنسخ متن PEM ولا قيمة INTERNAL_SERVICE_TOKEN.

Public routes

From compose/dynamic.yaml, which Kind mounts as the gateway file provider:

  • Reports go to reporting on port 8001, with JWT.
  • Device tokens go to notification on port 8002, with JWT.
  • Public auth POSTs (register, login, refresh, logout) go to order on port 8000 without JWT.
  • Other /api/v1 paths, except /api/v1/internal, go to order with JWT.
  • Everything else, except /api and /ping, goes to the frontend.

How it works

Compose services and keys

One Docker network named commerce. Containers find each other by Compose DNS. Published ports bind 127.0.0.1 only: gateway 8080, RabbitMQ management 15672, Odoo 8069, Grafana 3000, Prometheus 9090, Alertmanager 9093. Postgres and Redis are not published.

The private JWT PEM is mounted only into the order HTTP process. The public PEM is mounted into jwt-check, the order HTTP process, reporting (migrate, API, consumer), and notification (API and consumer). The frontend does not receive either key or INTERNAL_SERVICE_TOKEN. That token is shared by the order HTTP process and the Odoo connector so fulfillment can call the order service on the private network. An empty token makes those routes return 503.

Images we build use tag 0.1.0 (Odoo 18.0.1). latest is not used. up.sh does not delete volumes. The saga worker is not a Compose service.

Gateway middlewares

edge-prepare strips client identity headers (user, role, account, and X-Internal-Token), normalizes X-Correlation-Id to a UUID, and stamps an allow-list CORS response. Allowed origins are localhost and 127.0.0.1 on ports 8080 and 5173. The allow-list is not *. edge-cors answers OPTIONS with 204 so a preflight never reaches JWT or an upstream. coarse-limit is Traefik’s in-memory limiter: average 30 requests per second, burst 60, one counter per process. It is not the Redis login or order-create budget. jwt-access is ForwardAuth to jwt-check:8081/verify. The checker accepts an RS256 Bearer access token with exp, iat, and sub. It does not enforce roles. The order and reporting services verify the token again.

Kind differences

Postgres Service names are order-postgres, reporting-postgres, notification-postgres, and odoo-postgres (Compose calls the order database service postgres and the Odoo database odoo-db). Grafana, Prometheus, Odoo, and RabbitMQ management stay ClusterIP. The only host door is still 127.0.0.1:8080. Static hostPath volumes hold Postgres, RabbitMQ, Odoo filestore, Prometheus, Grafana, and Tempo. Redis has no volume.

Order path

An init container or a one-shot service runs Alembic migrate, then the HTTP API starts. Orders are rows in order_db. One outbox publisher claims rows with FOR UPDATE SKIP LOCKED and stays at one replica so publish order follows created_at. Inventory consumers compete on q.order.inventory. On Kind the order API starts at 2 replicas and an HPA holds it between 2 and 4 on CPU at 70 percent. The HPA does not watch queue depth. A CronJob at 03:30 UTC runs nightly retention (365 days, batches of 100, at most 20 batches) and does not scale the API.

Trace path

Order processes, reporting, and the gateway send OTLP to otel-collector:4317. The collector forwards traces to Tempo and keeps them about 24 hours. Prometheus scrapes /metrics directly so a collector outage cannot hide an error rate. Alertmanager groups by alert name and posts to the webhook, which writes one JSON line per alert to stdout. There is no email and no secret in that hop. Checkout does not wait on this stack.

Backup, failure lab, and load bars

dump.sh takes one argument, order_db, reporting_db, or odoo_db, and writes a custom-format dump. restore.sh needs that name, a dump file, and --yes. The archive header must name the same database. A restore is not a rewind of RabbitMQ or Redis.

Each failure-lab script accepts stop or start for one service and prints what to look at. Stopping the reporting consumer still lets confirm succeed; the projection catches up on start. Stopping RabbitMQ still lets the order HTTP call commit; the outbox row stays pending. Stopping Redis leaves catalog reads on Postgres and makes login and order create fail closed. Stopping the inventory consumer still lets confirm succeed; q.order.inventory grows when inventory events are published.

Gentle load: 2 users, 15 seconds between attempts, no failures, no HTTP 429, and p95 under 2000 ms. Flood load: 1 user, 0.2 seconds between attempts, 15 order creates, at least one HTTP 429 with code RATE_LIMITED, and no other failure. RESULTS.md records that this environment had not run Locust because Docker was down.

كيف يعمل

خدمات Compose والمفاتيح

شبكة Docker واحدة اسمها commerce. تجد الحاويات بعضها بأسماء DNS في Compose. المنافذ المنشورة مربوطة بـ 127.0.0.1 فقط: البوابة 8080، وإدارة RabbitMQ 15672، وOdoo 8069، وGrafana 3000، وPrometheus 9090، وAlertmanager 9093. Postgres وRedis غير منشورين.

يُركَّب ملف PEM الخاص لـ JWT في عملية HTTP للطلبات فقط. يُركَّب الملف العام في jwt-check وعملية HTTP للطلبات والتقارير (الترحيل وواجهة البرمجة والمستهلك) والإشعارات (واجهة البرمجة والمستهلك). الواجهة لا تتلقى أي المفتاحين ولا INTERNAL_SERVICE_TOKEN. يتشارك هذا الرمز عملية HTTP للطلبات وموصّل Odoo حتى يستدعي التنفيذ خدمة الطلبات على الشبكة الخاصة. الرمز الفارغ يجعل تلك المسارات تُرجع 503.

الصور التي نبنيها تستخدم الوسم 0.1.0 (وOdoo 18.0.1). الوسم latest غير مستخدم. up.sh لا يحذف المجلدات. عامل الساجا ليس خدمة Compose.

وسائط البوابة

يزيل edge-prepare ترويسات هوية العميل (المستخدم والدور والحساب وX-Internal-Token)، ويطبّع X-Correlation-Id إلى UUID، ويختم استجابة CORS من قائمة مسموحة. الأصول المسموحة هي localhost و127.0.0.1 على المنفذين 8080 و5173. القائمة ليست *. يجيب edge-cors على OPTIONS بالحالة 204 حتى لا يصل طلب التحضير إلى JWT أو إلى خدمة خلفية. coarse-limit محدّد Traefik في الذاكرة: متوسط 30 طلباً في الثانية ودفعة 60، وعداد واحد لكل عملية. ليس ميزانية الدخول أو إنشاء الطلب في Redis. jwt-access هو ForwardAuth إلى jwt-check:8081/verify. يقبل الفاحص رمز وصول Bearer بتوقيع RS256 وفيه exp وiat وsub. لا يفرض الأدوار. تعيد خدمتا الطلبات والتقارير التحقق من الرمز.

فروق Kind

أسماء خدمات Postgres هي order-postgres وreporting-postgres وnotification-postgres وodoo-postgres (في Compose اسم خدمة قاعدة الطلبات postgres واسم قاعدة Odoo odoo-db). تبقى Grafana وPrometheus وOdoo وإدارة RabbitMQ من نوع ClusterIP. الباب الوحيد على المضيف يبقى 127.0.0.1:8080. مجلدات hostPath الثابتة تحفظ Postgres وRabbitMQ ومخزن ملفات Odoo وPrometheus وGrafana وTempo. Redis بلا مجلد.

مسار الطلب

يشغّل حاوية تهيئة أو خدمة لمرة واحدة ترحيل Alembic، ثم تبدأ واجهة HTTP. الطلبات صفوف في order_db. ناشر صندوق الصادر واحد يحجز الصفوف بـ FOR UPDATE SKIP LOCKED ويبقى بنسخة واحدة حتى يتبع النشر ترتيب created_at. يتنافس مستهلكو المخزون على q.order.inventory. في Kind تبدأ واجهة الطلبات بنسختين ويبقيها HPA بين 2 و4 حسب المعالج عند 70 بالمئة. لا يراقب HPA عمق الطابور. مهمة مجدولة عند 03:30 بالتوقيت العالمي تشغّل الاحتفاظ الليلي (365 يوماً، دفعات من 100، وعلى الأكثر 20 دفعة) ولا توسّع الواجهة.

مسار التتبع

ترسل عمليات الطلبات والتقارير والبوابة OTLP إلى otel-collector:4317. يمرّر المجمّع الآثار إلى Tempo ويحتفظ بها نحو 24 ساعة. يسحب Prometheus المسار /metrics مباشرة حتى لا يخفي تعطل المجمّع معدّل الأخطاء. يجمع Alertmanager حسب اسم التنبيه ويرسل إلى الخطاف، الذي يكتب سطراً واحداً من JSON لكل تنبيه على المخرج القياسي. لا بريد ولا سر في هذه القفزة. إتمام الشراء لا ينتظر هذا المكدس.

النسخ، ومختبر الأعطال، وعتبات الحمل

يأخذ dump.sh وسيطاً واحداً: order_db أو reporting_db أو odoo_db، ويكتب نسخة بصيغة custom. يحتاج restore.sh إلى ذلك الاسم وملف النسخة و--yes. يجب أن يسمّي ترويسة الأرشيف قاعدة البيانات نفسها. الاستعادة ليست إرجاعاً لـ RabbitMQ أو Redis.

يقبل كل سكربت في مختبر الأعطال stop أو start لخدمة واحدة ويطبع ما يُنظر إليه. إيقاف مستهلك التقارير يُبقي التأكيد ناجحاً، ويلحق الإسقاط عند التشغيل. إيقاف RabbitMQ يُبقي استدعاء HTTP للطلب ملتزماً في القاعدة، ويبقى صف صندوق الصادر معلّقاً. إيقاف Redis يُبقي قراءة الفهرس من Postgres ويجعل الدخول وإنشاء الطلب يفشلان مغلَقين. إيقاف مستهلك المخزون يُبقي التأكيد ناجحاً، وينمو q.order.inventory عند نشر أحداث المخزون.

الحمل الهادئ: مستخدمان، و15 ثانية بين المحاولات، وبلا إخفاقات، وبلا HTTP 429، وp95 تحت 2000 مللي ثانية. حمل الغمر: مستخدم واحد، و0.2 ثانية بين المحاولات، و15 إنشاء طلب، وعلى الأقل HTTP 429 بالرمز RATE_LIMITED، وبلا إخفاق آخر. يسجّل RESULTS.md أن هذه البيئة لم تشغّل Locust لأن Docker كان متوقفاً.

backup/

Compose Postgres only. notification_db, Redis, and RabbitMQ are out of scope. Dumps land in backup/dumps/, which the scripts create on demand and which is not in the tree until a dump runs.

PathResponsibilityHow it works
backup/Dump and restore helpers.Scripts source lib.sh and talk to Compose services postgres, reporting-postgres, and odoo-db.
lib.shShared checks. Not a backup by itself.Refuses any database name other than the three. Reads POSTGRES_DB inside the container and refuses a mismatch. Reads the archive header with pg_restore --list and refuses a cross-database dump. A failing docker info returns before any dump or restore. The file name is not the database name.
dump.shOne custom-format dump.Usage: dump.sh order_db|reporting_db|odoo_db. Runs pg_dump --format=custom --no-owner --no-acl inside that service. Writes a partial file first and removes it on failure. Prints the final path dumps/<db>-<utc>.dump.
restore.shReplace objects inside one database.Usage: restore.sh <db> <dump-file> --yes. Refuses a missing --yes, an unknown option, or a missing file. pg_restore --clean --if-exists --single-transaction replaces objects in that database only. Records start, end, and elapsed seconds in dumps/last-restore.txt.
test_backup.pyStatic checks.Does not dump or restore a database. Reads the scripts and checks the Phase 19 contract.

backup/

Postgres في Compose فقط. notification_db وRedis وRabbitMQ خارج النطاق. تقع النسخ في backup/dumps/، وينشئه السكربت عند الطلب وليس في الشجرة قبل تشغيل نسخة.

test_scenario.pyStatic checks for the plan.Does not start Locust and does not call the API.
RESULTS.mdLast run note.States that this environment did not run the test: Docker was down, no requests were sent, and no latency was measured. A later Locust run replaces the file with that process’s counts.

failure-lab/

One Compose service at a time. The helpers refuse any command other than stop or start, and refuse a service name other than the one that script owns. A failing docker info returns before anything is stopped.

PathResponsibilityHow it works
failure-lab/Stop/start drills against deploy/compose.Each script prints the expected HTTP result and the queue or table to look at. They do not change limits or delete rows.
lib.shShared guard. Not a drill by itself.Resolves the Compose file next door. compose accepts only stop or start and only the SERVICE variable that script set.
reporting-consumer.shDrill for reporting-consumer.Stop: confirm still returns 200 and status CONFIRMED. q.reporting.projection grows because the publisher still sends. Reporting can answer from rows already in reporting_db. Start: the consumer drains the queue and a duplicate event_id is acked without a second projection write.
rabbitmq.shDrill for rabbitmq.Stop: create and confirm still commit in order_db. The outbox row stays pending. After five failed publish attempts the row becomes failed and is not claimed again until a person sets it back to pending. Start: pending rows publish. Already published rows are not invented again. This is not a rewind of the broker.
redis.shDrill for redis.Stop: product list still returns 200 from Postgres. Login, register, and order create return 503 DEPENDENCY_UNAVAILABLE before a session or an order row is written. Confirm, order read, refresh, and logout do not use Redis. jwt-check does not use Redis. Start: those routes work again and the Redis limits apply again (login 5 per minute, order create 10 per minute).
inventory-consumer.shDrill for order-inventory-consumer.Stop: confirm still succeeds. Confirm is not routed to q.order.inventory. That queue grows when odoo-publisher sends InventoryUpdated. Start: one event_id updates the inventory snapshot once. A second delivery is acked as a duplicate.
test_lab.pyStatic checks.Does not start Docker and does not stop a service. Reads the scripts and checks the Phase 18 contract.
